# 定义表 qualiscore

## 1 列契约

固定 10 列，顺序即单元格账的列顺序；表头按别名映射（中文表头、带空格或括号都认）。

| 列名 | 表头 | 类型 | 单位 / 刻度 | 取值范围 | 说明 |
|---|---|---|---|---|---|
| `ticket_id` | 工单号 | 字符串保形 | — | `T-YYYY-NNNNNN` 或 6-19 位数字 | 业务键；19 位大整数不过 `int()` |
| `customer_id` | 客户号 | 字符串保形 | — | 3-8 位数字 | 前导零保留，`00123` 与 `123` 是两个客户 |
| `channel` | 渠道 | 枚举 | — | 电话 / 在线 / 邮件 / 门店 | 大小写与全角先折半角再比对 |
| `created_at` | 受理时间 | 时间 | 入库 UTC，展示 +08:00 | ISO8601 | 带偏移按偏移换算；无偏移按 +08:00 |
| `first_response_min` | 首响(分钟) | 小数 | 分钟 / 0.1 | 0 – 2880 | 千分位、全角数字先归一 |
| `handle_hours` | 处理时长(小时) | 小数 | 小时 / 0.01 | 0 – 720 | 同列混写小数位时按 0.01 量化 |
| `satisfaction` | 满意度 | 整数 | 分 / 1 | 1 – 5 | 1-5 分刻度粗，离散度低于 5 判退化 |
| `agent` | 受理人 | 文本 | — | 非空 | 整列为空时记「全空列」 |
| `region` | 区域 | 文本 | — | 非空 | 与 `agent` 常同起同落，看共缺对 |
| `priority` | 优先级 | 枚举 | — | P1 / P2 / P3 | 不在枚举内记格式不合格 |

## 2 单元格三态

| 状态 | 判定 | 原因码 | 是否进缺失账 |
|---|---|---|---|
| 缺失 | 空串 | `K_NULL` | 是 |
| 缺失 | 空白串（只有空格、全角空格） | `K_BLANK` | 是 |
| 缺失 | 哨兵：`-` `--` `—` `/` `N/A` `NULL` `NONE` `未知` `无` `暂无` `待定` `空` `未填` | `K_SENTINEL_NULL` | 是 |
| 格式不合格 | 无法解析成该列类型 | `K_BAD_FORMAT` | 否，进格式账 |
| 格式不合格 | 能解析但越界（如满意度 7、首响 −3） | `K_OUT_OF_RANGE` | 否，进格式账 |
| 有值 | 解析成功且在范围内 | — | 否，进有值账 |

三条恒等式：

1. 单元格 = 缺失 + 有值
2. 有值 = 合格 + 格式不合格
3. 离群格 ⊆ 合格格（只从数值列、且该列未退化时产生）

优先级（TRAP-19）：缺失 > 格式不合格 > 离群。一个单元格只拿到一个状态与一个原因码。

## 3 时间

- 入库统一 UTC（`+00:00`），页脚与页面按 `Asia/Shanghai (+08:00)` 显示。
- `Z` 结尾、`+08:00`、无偏移三种写法都归一到同一时刻；无偏移按单据本地时区 +08:00 处理。
- 运行记录时间戳用 UTC ISO8601 秒级；表格里显示本地时间。

## 4 去重键

| 账 | 键 | 用途 | 与另一账的关系 |
|---|---|---|---|
| 全行哈希 | 10 列规范化后整行的 sha256 | 「采纳行 = 唯一 + 重复」 | 决定重复率与重复维扣分 |
| 业务键 | `ticket_id` | 同键重复、同键冲突 | 只做归因，不改变行账 |

- 缺失格参与哈希时用固定占位符 `\u0000MISSING`，避免「都缺这一列」被当成不同行。
- 格式不合格格用 `!` + 原值参与哈希，保证同一份坏数据两次运行哈希一致。
- 同键不同值：两行都保留原值，冲突列逐列列出；系统不猜哪条为准。

## 5 评分常量

| 维度 | 封顶分 | 容忍度 | 比率分母 | 说明 |
|---|---:|---:|---|---|
| 缺失 | 30 | 8% | 单元格总数 | 缺失格 / 单元格 |
| 重复 | 25 | 6% | 采纳行 | 全行重复行 / 采纳行 |
| 离群 | 20 | 10% | 参检格 | 离群格 / 参检格（已排除退化列） |
| 格式 | 25 | 5% | 有值格 | 格式不合格格 / 有值格 |

- 每维扣分 = 封顶分 × min(1, 实际比率 ÷ 容忍度)，量化 0.01（ROUND_HALF_UP）。
- 总分 = 100 − 扣分之和，量化 0.01，恒在 [0, 100]；`总分 + 扣分之和 = 100` 逐位成立。
- 等级：A ≥ 90、B ≥ 75、C ≥ 60、其余 D；等级标签依次为可用 / 待复核 / 需返工 / 不可用。
- 严重度 = 该维扣分 ÷ 该维封顶分：≥ 0.60 严重、≥ 0.30 警告、> 0 提示、0 通过。

## 6 稳健离群

- 中位数：偶数个取中间两值均值；`MAD = median(|x − 中位数|)`。
- `z = 0.6745 × (x − 中位数) / spread`，阈值 `|z| > 3.5`。
- MAD = 0 时 `spread = 0.6745 × IQR / 1.349`（等价于 `z = 1.349 × (x − 中位数) / IQR`）。
- `spread` 低于「列刻度 × 5」或 MAD 与 IQR 同为 0 → 该列判退化，标 `K_DEGENERATE`，不产生离群格。
- 参检样本少于 4 个 → 方法记 `insufficient`，同样不产生离群格。

## 7 缺失模式

- 连续缺失段：同一列按原始行序连续缺 ≥ 3 个单元格记一段，起止都用源文件行号。
- 缺失签名：一行里缺失列名的有序元组；同签名行数 ≥ 1 即进模式表。
- 共缺对：两列在同一行同时缺失 ≥ 2 行才记一对。
- 全空列：整列 100% 缺失，单独标出，不算「填充率低的列」。

## 8 运行记录

| 字段 | 含义 |
|---|---|
| `run_id` | `QS-<UTC 时间戳>-<4 位随机>`，一次运行一个 |
| `input_digest` | 文件名 + 文件字节 sha256 + 规则版本与阈值摘要 的 sha256 |
| `rules_digest` | 权重、容差、等级阈值、稳健系数的摘要 |
| `version` | 同名数据集自增版本号，陈旧提交靠它拦 |
| 幂等键 | (`数据集名`, `input_digest`, `rule_version`) 唯一，重复运行直接复用 |

## 9 原因码

完整清单见 `app/reasons.py`，前缀含义：`E_` 文件级失败（4xx，整批不落数据）、
`Q_` 行级隔离（进隔离区，带行号与原值）、`K_` 标记（不进隔离区，只留证据）、
`R_` 修订逐单状态（只出现在修订账与修订导出里）。

## 10 修订补发

报告发布后，客服补回只含**部分工单**的更正文。修订不重导整份文件，而是在
上一次运行的采信快照上按业务键改写被点名的工单，生成一条新版本。

### 10.1 匹配

| 规则 | 处理 |
|---|---|
| 匹配键 | 业务键 `ticket_id`（规范化口径同 §4 去重键），**不用行号** |
| 行号 | 更正文行号与报告行号无对应关系；只留痕，不参与匹配 |
| 可改列 | 更正文表头出现哪几列就只改哪几列；必须含工单号，且至少有一列可改 |
| 空单元格 | 表示「这一列不改」；要清空请写空值哨兵（`-` / `N/A` 等，见 §2） |
| 同工单多行 | 规范化后改法一致 → 视为一次更正并留 `R_CORRECTION_DUPLICATE`；改法冲突 → 待核对 |
| 基线同键多行 | 各行完全相同（纯重复）→ 一起改写；取值不同（业务键冲突）→ 待核对，不猜 |
| 结构坏行 | 更正文列数与表头不一致 → 不丢弃，进待核对并留 `R_CORRECTION_MALFORMED` |

### 10.2 逐单状态（互斥三分）

| 状态 | 判定 | 原因码 |
|---|---|---|
| 已更正 | 找到原始工单且至少一格真的改写 | `R_CORRECTED` |
| 保持原样 | 找到原始工单，但更正文取值与原文一致或没带可改列 | `R_CORRECTION_NO_CHANGE` / `R_KEPT_ORIGINAL` |
| 待核对 | 找不到原始工单 / 同键多值 / 更正文重复且冲突 / 结构坏行 | `R_CORRECTION_UNMATCHED` / `R_CORRECTION_AMBIGUOUS` / `R_CORRECTION_MALFORMED` |

修订页面与 `revision.csv` 逐单给出这三个状态；报告页给出三态计数。

### 10.3 阻断决策

- **未匹配内容不阻断修订**：只要有至少一条工单能对上基线，已匹配部分照常发布，
  未匹配 / 重复 / 歧义的行保留为「待核对」，不静默丢弃。
- 只有**一条工单都对不上**（或更正文没有任何可用数据行）时才整批拒绝，
  返回 `R_REVISION_EMPTY`（409），旧版保持不变。
- 待核对项**跨版本结转**：这一版没对上的建议值随修订账存下来，下一版先尝试
  把它们对回；解决前一直留在账上，不丢记录。

### 10.4 版本、幂等与失败回滚

| 约束 | 实现 |
|---|---|
| 不重算已通过记录 | 修订读基线运行的**采信快照**（原文 + 解析结果），不重导数据集当前内容 |
| 基线不可变 | 修订不改写基线运行、不改写数据集原文；基线运行始终可读 |
| 叠加 | 第二份更正文默认修「已发布的上一版」；显式 `base_run_id` 可改基线 |
| 同一更正重试 | 按（基线原文摘要 + 更文字节摘要 + 规则版本）在修订链上查重，命中即复用，**不重复扣分、不多加版本** |
| 版本自增 | 版本号在落库事务内现取，`UNIQUE(name, version)` 兜底并发 |
| 中途失败 | 运行行、采信快照、修订账在**同一事务**写入；任一步失败整体回滚，旧版仍是最近运行 |

修订运行的 `input_digest = sha256(基线原文摘要, 更正文摘要)`，清单另记
`base_input_digest` 与 `correction_digest`，两者可分别复算。
